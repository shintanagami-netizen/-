## コンサルティング品質基準（全モード共通・最優先）

> **核心原則**: 1秒で結論が伝わり、反論の余地がない構成にする。文字数ではなく「判断の質」で評価する。

### ① ワンスライド・ワンメッセージ
- 各スライドの先頭リード文（`>`）は「**So What?（判断を促す結論）**」として記述
- 状況説明・事実の羅列は禁止。「だから何か」「次に何をすべきか」を1〜2文で
- 例: ❌「3つの課題があります」 → ✅「3課題の根本は1点：型がない。ここを解くと全てが動く」

### ② テキスト削減の鉄則
- 1箇条書き = **25字以内**（それ以上は分割 or 図解へ）
- サブ箇条書きは1階層まで。2階層以上はテーブルか2カラムへ変換
- 「〜という構造」「〜のため」等の接続語・説明語は削除

### ③ 図解優先（テキスト羅列禁止）
- 3要素以上の並列 → テーブル or 2カラム
- 因果関係・対比（現状 vs 解決策） → 2カラム（`::left` / `::right`）
- ステップ・フロー → 番号付きリスト（1. 2. 3.）
- 数値・KPI → テーブルの1行にまとめる

### ④ 情報の重み付け（急所を1つ決める）
- 各スライドで「最も伝えたい1点」を **太字** で強調
- 補足情報はサブ箇条書き or フッター的扱い（小さく）

### ⑤ Audience定義に基づく言語選択
- 経営層向け: 数値・ROI・リスクを前面に
- 現場向け: 具体的アクション・プロセスを前面に
- 営業企画向け: KPI（受注率・転換率・立ち上がり期間）と介入ポイントを前面に

## モード判定

| 条件 | 実行モード |
|------|-----------|
| `.md` ファイルパスが引数に渡された | **モードA: Markdown → pptx 生成** |
| スライドテキストが貼り付けられた・「このスライドを改善」等 | **モードC: スライド内容レビュー＆再生成** |
| 「提案書」「提案資料」「〇〇に△△を提案」「営業提案」等のトリガーワード | **モードB: 提案資料 自動生成（2フェーズ）** |
| 引数なし・曖昧な場合 | ユーザーに確認する |

## モードC: スライド内容レビュー＆再生成

テキストが貼り付けられたスライド内容を、コンサルティング・スタンダードで再設計してpptxを生成する。

### Step 1: スライドごとにコンサル診断

各スライドに対して以下を出力:
- **メッセージライン（So What?）**: 判断を促す結論1〜2文
- **ボディ構成案**: テーブル / 2カラム / 番号付きリスト のどれで表現するか
- **削減対象**: カットすべき冗長表現

### Step 2: 再設計Markdownを生成してpptxを出力

```bash
python generate_ppt.py <出力名>.md <出力名>.pptx logo.png
```

## モードA: Markdown → pptx 生成

```bash
python generate_ppt.py <入力.md> <出力.pptx> logo.png
```

- 出力ファイル名は入力と同名・拡張子 `.pptx`（例: `input.md` → `input.pptx`）
- `logo.png` が存在しない場合は引数を省略
- 生成完了後、出力ファイル名を報告する

## モードB: 提案資料 自動生成（2フェーズ）

**核心思想**: 感動する提案は「素材（=顧客情報）の質」で決まる。調査の深さが提案の質を決定する。

### フェーズ1: 情報収集 → 提案骨子 → ワイヤーフレームレビュー

#### Step 1: ヒアリング

- **提案元企業**: 企業名、主要プロダクト/サービス
- **提案先企業**: 企業名
- **追加資料**: ヒアリングメモ・企業理解ドキュメントがあれば添付依頼
- **提案の方向性**（任意）: フォーカスしたい領域・課題

#### Step 2: 企業調査

Web検索15〜25回、web_fetch は有望URLのみ8件以内。添付資料があれば優先活用。

**提案元調査:** 企業概要・プロダクト一覧・強み・導入事例（3〜5件）・最新ニュース

**提案先調査（★重点）:**

| 調査項目 | 着眼点 |
|---------|--------|
| 企業概要・IR | 売上規模、従業員数、拠点数 |
| 事業内容・サービス | 全サービスの把握 |
| 中期経営計画・ビジョン | 目指す方向性、成長戦略 |
| 業界動向・KSF | 業界全体の課題と機会 |
| 直近ニュース | 新規事業、M&A、組織変更 |
| 採用情報 | 注力領域の推測 |
| 競合情報 | ポジショニングの把握 |

調査結果を `/home/user/-/{proposal_name}/research_results.md` に保存する。

#### Step 3: 提案骨子の構造化

以下の構成で骨子を生成し、`/home/user/-/{proposal_name}/proposal_outline.md` に保存:

1. タイトルスライド（事業方向性に紐づいたキャッチーなタイトル）
2. 目次
3. 貴社の目指す状態 / 現在の取り組み / 課題（提案元が解決できることに紐づける）
4. 解決策の全体像（ブロック図）
5〜7. 提案1〜3（現状課題 → ソリューション → 実現イメージ）
8. 技術統合アーキテクチャ（既存システムとの連携図）
9. 導入ロードマップ（フェーズ1: 1〜3ヶ月 / 2: 3〜6ヶ月 / 3: 6ヶ月〜）
10. 投資対効果（ROI）
11. 成功事例（類似業界・規模）
12. ネクストステップ
13. ワオポイント（まとめ・「なぜ今やるべきか」）

**品質基準:**
- 「物」ではなく「事」を提案する（機能列挙 → 事業成果）
- 経営方針・ビジョンから課題を導く
- 課題は提案先視点で書く（「そうそう、それが課題」と思える表現）
- 可能な限り定量的（○%削減、○ヶ月短縮等）

#### Step 4: ワイヤーフレーム可視化

点線枠・ブロック図・矢印で各スライドの構造を図示する。テキスト羅列ではなく要素間の関係性（階層・因果・並列）を表現。

#### Step 5: 🛑 停止・ユーザー確認

```
フェーズ1（提案骨子）が完了しました。

■ ワイヤーフレームをご確認ください。
  - 構成の順序は適切ですか？
  - 追加・削除したいスライドはありますか？
  - 課題の捉え方は提案先の実態に合っていますか？

修正がなければ「OK」と送ってください → フェーズ2（pptx生成）に進みます。
```

修正依頼があれば骨子を修正 → ワイヤーフレームを再生成 → 再確認。

---

### フェーズ2: 提案資料化（ユーザー承認後のみ実行）

#### Step 6: pptx生成

`proposal_outline.md` をもとに Markdown を生成してから pptx を生成する:

```bash
python generate_ppt.py {proposal_name}.md {proposal_name}.pptx logo.png
```

**スライドデザインの原則:**
- 図解・ブロック図・矢印で情報の流れを表現（テキスト羅列禁止）
- 1スライド1メッセージ
- テーブル・2カラム・区切り線を積極活用
- レイアウトを変化させる（同一レイアウトの繰り返し禁止）

#### Step 7: 納品

ファイルの存在・スライド枚数・サイズを確認し、出力パスを報告する。

## 実装上の必須ルール

1. フォント: 全要素に `Meiryo UI` を設定
2. シャドウ除去: 全シェイプに `remove_shadow()` を適用
3. テーブルセル背景: `set_cell_bg()` でXML直接操作
4. テキストボックス: `word_wrap = True` を必ず設定
5. スライドレイアウト: 常に `prs.slide_layouts[6]`（blank）を使用
6. 縦の装飾ライン: 使用しない

---

## 禁止事項

- フェーズ1完了時にユーザー確認なしでフェーズ2に進む
- 調査を省略して骨子を作る
- プロダクト機能を羅列して提案する（事業方向性への紐づけが必須）
- テキストを羅列してスライドを構成する（図解・構造表現が必須）
- 課題を提案元視点で書く
- 縦の黒い装飾ラインを追加する
