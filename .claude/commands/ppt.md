このスキルは **2つのモード** を持つ。引数・文脈に応じて自動判定して実行する。

---

## モード判定

| 条件 | 実行モード |
|------|-----------|
| `.md` ファイルパスが引数に渡された | **モードA: Markdown → pptx 生成** |
| 「提案書」「提案資料」「〇〇に△△を提案」「営業提案」等のトリガーワード | **モードB: 提案資料 自動生成（2フェーズ）** |
| 引数なし・曖昧な場合 | ユーザーに確認する |

---

## モードA: Markdown → pptx 生成

### 手順

1. ユーザーが指定したMarkdownファイル（または引数 `$ARGUMENTS`）を確認する
2. 出力ファイル名はMarkdownのファイル名と同じ名前で `.pptx` 拡張子にする（例: `input.md` → `input.pptx`）
3. 以下のコマンドを実行する：

```bash
python generate_ppt.py <入力.md> <出力.pptx> logo.png
```

4. 生成完了後、出力ファイル名を報告する

### 重要

- CLAUDE.md に記載された設計仕様・カラーパレット・レイアウトルールを必ず守ること
- `logo.png` が存在しない場合は引数を省略する
- Markdownファイルが存在しない場合はユーザーに確認する

## モードB: 提案資料 自動生成（2フェーズ）

**核心思想**: 感動する提案は「素材（=顧客情報）の質」で決まる。調査の深さが提案の質を決定する。

### トリガーワード

- 提案書を作りたい / 提案資料を作って
- 〇〇に△△を提案したい
- 提案の骨子を作って
- 〇〇向けの提案
- 営業提案 / クライアント提案
- ソリューション提案

---

### フェーズ1: 情報収集 → 提案骨子 → ワイヤーフレームレビュー

#### Step 1: ヒアリング

ユーザーに以下を確認する:

- **提案元企業**（= 提案する側）: 企業名、主要プロダクト/サービス
- **提案先企業**（= 提案を受ける側）: 企業名
- **追加資料の有無**: 企業理解ドキュメント、ヒアリングメモ等があれば添付を依頼
- **提案の方向性**（任意）: 特にフォーカスしたい領域・課題があれば

#### Step 2: 企業調査

提案元・提案先の両方を調査する。Web検索は15〜25回を目安、web_fetchは有望URLのみ合計8件以内。ユーザー添付資料がある場合は優先活用。

**2-1. 提案元企業の調査**

| 調査項目 | 検索例 |
|---------|--------|
| 企業概要・事業内容 | `{company} 会社概要 事業内容` |
| プロダクト/サービス一覧 | `{company} サービス 製品 機能 料金` |
| 強み・差別化ポイント | `{company} 強み 特徴 選ばれる理由` |
| 導入事例（3〜5件） | `{company} 導入事例 ケーススタディ` |
| 最新ニュース・リリース | `{company} ニュース プレスリリース 2025` |

**2-2. 提案先企業の調査（★重点調査）**

| 調査項目 | 検索例 | 着眼点 |
|---------|--------|--------|
| 企業概要 | `{company} 会社概要 IR` | 売上規模、従業員数、拠点数 |
| 事業内容・サービス | `{company} サービス 事業` | 全サービスの把握 |
| 経営方針・ビジョン | `{company} 中期経営計画 ビジョン` | 目指す方向性、成長戦略 |
| 業界動向・KSF | `{industry} 業界動向 課題 トレンド` | 業界全体の課題と機会 |
| 直近ニュース | `{company} ニュース 2025` | 新規事業、M&A、組織変更 |
| 採用情報 | `{company} 採用 求人 エンジニア` | 注力領域の推測 |
| 競合情報 | `{company} 競合 比較 vs` | ポジショニングの把握 |

**2-3. 調査結果のファイル保存**

`/home/user/-/{proposal_name}/research_results.md` に以下の構造で保存:

```markdown
# 提案調査結果: {提案元} → {提案先}
## 1. 提案元企業の概要
### 企業概要
### プロダクト/サービス一覧
### 強み・差別化ポイント
### 主要導入事例
## 2. 提案先企業の概要
### 企業概要
### 事業内容・サービス一覧
### 経営方針・ビジョン・目指す方向性
### 直近ニュース・リリース
### 採用情報から読み取れる注力領域
### 業界動向・KSF
## 3. 提案の着眼点メモ
- 提案先の事業方向性に対して提案元が貢献できるポイント
- 採用情報や投資から推測される課題
- 業界トレンドとの接続点
```

#### Step 3: 提案仮説の構造化

調査結果に基づき、以下のスライド構成で提案骨子を生成する:

1. **タイトルスライド** — キャッチーな提案タイトル（事業方向性に紐づいた表現）
2. **目次** — 全体の構成を俯瞰
3. **貴社の目指す状態 / 現在の取り組み / 問題要因・課題** — 3つ程度の戦略的チャレンジ（課題は提案元が解決できることに紐づける）
4. **解決策の全体像** — ブロック図でアーキテクチャを図示
5〜7. **提案1〜3**（各1〜2スライド）— 現状課題 → ソリューション → 実現イメージ
8. **技術統合アーキテクチャ** — 既存システムとの連携図・データフロー
9. **導入ロードマップ** — フェーズ1（1〜3ヶ月）/ フェーズ2（3〜6ヶ月）/ フェーズ3（6ヶ月〜）
10. **投資対効果（ROI）** — 導入コスト概算・削減効果・ROI計算
11. **成功事例** — 類似業界・規模の導入事例
12. **ネクストステップ** — ヒアリング→PoC→導入のアクション
13. **ワオポイント（まとめ）** — 3〜4つのキーメッセージ・「なぜ今やるべきか」

**骨子の品質基準:**
- 「物」ではなく「事」を提案する（機能列挙ではなく事業成果を提案）
- 事業方向性に紐づける（経営方針・ビジョンから課題を導く）
- 課題は提案先視点で書く（「そうそう、それが課題」と思える表現）
- 可能な限り定量的な表現を入れる（○%削減、○ヶ月短縮等）

骨子を `/home/user/-/{proposal_name}/proposal_outline.md` に保存する。

#### Step 4: ワイヤーフレーム可視化

骨子をもとに、スライド構成のワイヤーフレームをテキストまたは図でユーザーに提示する。
- スライド領域は点線枠で概念的に表現
- ブロック図と矢印で情報の流れ・構造を説明
- テキストの羅列ではなく、要素間の関係性（階層・因果・並列）を図解

#### Step 5: 🛑 停止・ユーザー確認

以下のメッセージで**必ず停止**する:

```
フェーズ1（提案骨子）が完了しました。

■ ワイヤーフレームをご確認ください。
  - 構成の順序は適切ですか？
  - 追加・削除したいスライドはありますか？
  - 各スライドの内容で修正したい点はありますか？
  - 課題の捉え方は提案先の実態に合っていますか？

修正がなければ「OK」と送ってください → フェーズ2（pptx生成）に進みます。
```

修正依頼があれば骨子を修正 → ワイヤーフレームを再生成 → 再度確認。

### フェーズ2: 提案資料化（pptx生成）

**フェーズ1でユーザーの承認を得てから**実行する。

#### Step 6: Markdown生成 → pptx生成

保存済みの `/home/user/-/{proposal_name}/proposal_outline.md` を読み込み、CLAUDE.md の記法・仕様に従って Markdown を生成してから pptx を生成する。

```bash
python generate_ppt.py {proposal_name}.md {proposal_name}.pptx logo.png
```

**スライドデザインの原則:**
- 情報の流れを図解で表現（テキスト羅列ではなくブロック図・矢印・構造図を多用）
- 1スライド1メッセージ（情報を詰め込みすぎない）
- レイアウトを変化させる（同じレイアウトの繰り返しを避ける）
- テーブル・2カラム・区切り線を積極的に活用する

#### Step 7: QA・確認

生成後にファイルの存在を確認し、スライド枚数・ファイルサイズを報告する。

#### Step 8: 納品

出力ファイルのパスをユーザーに報告する。

---

### 禁止事項

- フェーズ1完了時にユーザー確認なしでフェーズ2に進む
- 調査を省略して骨子を作る（調査の深さ = 提案の質）
- プロダクト機能の羅列で提案する（事業方向性への紐づけが必須）
- テキストの羅列でスライドを構成する（図解・構造表現が必須）
- 課題を提案元視点で書く（提案先が共感できる表現にする）
- 1回の応答で全フェーズを実行しようとする
