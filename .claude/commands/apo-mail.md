# アポ獲得メール作成スキル
SALESCOREのフィールドセールスが使用する、アポイント獲得に特化したメール文面作成のベストプラクティス集。
---
## 作業フロー
### Step 1：情報収集（必須）
メール作成前に以下を必ずリサーチする。
**企業側**
- 会社HP（会社概要・経営理念・MVV）
- 中長期経営計画・IR資料
- 採用情報・求人票（現場課題の裏返しが出やすい）
- オープンワーク等の口コミ（※ただしメール本文での引用は禁止）
**セミナー・トリガー側**
- 自社セミナーの場合：テーマ・登壇者・対象者属性を把握
- 第三者主催イベントの場合：イベントテーマと来場者の問題意識を推察
---
### Step 2：課題仮説の設計（最重要）
アポメールの命は「課題仮説の解像度」。以下の**主従構造**で設計する。

#### ❶ 課題仮説の主従構造（必須）
仮説は3点の等価列挙にしない。**主仮説2つ＋各1階層のドリルダウン**で構成する。

```
【主仮説①】核心的な課題を1文で描く
  └【従】その背景にある構造・根本原因を描く

【主仮説②】別角度からの課題を1文で描く
  └【従】その背景にある構造・根本原因を描く
```

**主仮説の選び方（この2軸をカバーする）：**
- 主仮説①：「方針と現場の乖離」系——変革の方針が現場の行動レベルに落ちていない
- 主仮説②：「ナレッジの構造問題」系——勝ちパターン・暗黙知が組織資産になっていない

→ 2軸をカバーすることで、①が外れても②で刺さるリスクヘッジになる。3点並列より2つの主従のほうが読み手の「確かに」を引き出しやすい。

#### ❷ 「御社の問題」ではなく「この変革を選んだ企業が直面する構造的な壁」として描く（絶対原則）

仮説の主語を「御社」にしない。**「この変革フェーズを進める企業が必ず直面する壁」として普遍化する**。これにより：
- 読んだ相手が「責められている」ではなく「わかってくれている」と感じる
- 「確かに…」という共感が「うちだけじゃないんだ」という納得に変わる
- 前向きな変革を断行した担当者・経営者の決断を否定せず、むしろ肯定した上で課題を提示できる

**NGフレーム（御社の問題として断定）：**
> 「マネージャーがフィードバックできていないのではないか」

**OKフレーム（このフェーズの構造的な壁として普遍化）：**
> 「提案型営業への転換期には、マネージャーが『何が良い提案か』の評価基準を持てないという壁がほぼ例外なく発生するのではないか——貴社においても同様の状況が生じていないか、推察しております」

**課題仮説ブロックの冒頭には必ず「評価・共感」を1文置く：**
> 「〇〇という変革を断行されたことは、業界的に見てもかなり踏み込んだ決断だと受け止めています。だからこそ、このフェーズで必ず直面する壁があるとも感じています」

**良い現場仮説の例：**
> 「ベテラン社員の勘と経験が暗黙知として蓄積されている一方、それが後輩や異領域担当者に伝わる仕組みがなく、マネージャーも『どうアドバイスすればいいか』が見えにくい——提案型営業への転換を進める組織では、このフェーズで必ずこの壁にぶつかるのではないか」

**悪い現場仮説の例（NGパターン）：**
> 「営業の属人化が課題になっているのではないか」→抽象すぎ、誰にでも当てはまる・「御社の問題」感が出る

### Step 3：文面設計のルール
#### 件名
```
[担当者名]様｜[トリガーに関連する一言]／SALESCORE株式会社 [送信者名]
```
#### 文面構成
1. **宛名**（部署名・氏名）
2. **書き出し**（所属・名前・トリガーへの言及）
3. **架電済みの場合**：電話した旨→メールに切り替えた旨
4. **つかみ**（セミナーテーマと担当者のお立場を繋ぐ一文）
4.5. **評価・共感の一文**（相手の変革・決断を前向きに認め「だからこそ」と繋ぐ）
5. **課題仮説ブロック**（＝＝＝で囲む、主仮説2つ＋各1階層ドリルダウンで構成）
6. **留保表現**（「外側からの仮説にすぎません」）
7. **弊社の支援実績・価値観の提示**（1〜2文）
8. **アポ打診**（「まずはご提案というよりも」）
9. **日程候補**（4〜5案）
10. **署名**
#### セミナートリガーの使い方
- **自社セミナーの場合**：参加御礼→テーマと担当者の関心を繋げる
- **第三者主催の場合**：来場した事実＝問題意識の証拠として活用。「来場した＝何を考えていたか」を仮説展開の入り口にする
---
## 文体・表現ルール
### 必須ルール
- 仮説は必ず **「〜ではないか」** で締める（断定しない）
- 課題仮説は **＝＝＝** で囲んで視覚的に分離する
- 「まずはご提案というよりも、現状の課題感をお伺いしたい」というスタンスを崩さない
- 「外側からの仮説にすぎません」の留保を必ず入れる
### 禁止事項
- **社内用語の使用禁止**：SEP、SYNC、Visualize、Buddy等
- **具体的な施策名の使用禁止**：朝会・夕会・1on1等の弊社固有の表現
- **未確認の役職名をメール本文に記載しない**（「正式かどうかわからない」場合は部署名のみ）
- **オープンワーク等の口コミを根拠として使用しない**
- **断定しすぎる表現**：「〜です」「〜になっています」→「〜ではないか」に置き換える
### 推奨表現
- 「私なりに現場で起きていることを以下のように推察しております」
- 「弊社がご支援してきた企業様においても〜」
- 「まずはご提案というよりも、現状の課題感を率直にお聞かせいただけないでしょうか」
- 「〇〇という決断は、業界的に見てもかなり踏み込んだ変革だと受け止めています。だからこそ——」（評価→仮説の接続）
- 「このフェーズを進める企業においてほぼ例外なく発生する壁として〜」（構造的な壁の普遍化）
- 「貴社に限らず、〇〇を選んだ組織が必ず直面するのが〜」（御社の問題化を回避する表現）

## 業種別の課題仮説設計パターン
### 製造業（BtoB・技術提案型営業）
- 技術部門・品質部門との連携が必要な複雑提案→担当者の経験値依存
- 長年の既存顧客関係→新規領域・新規顧客への展開で勝ちパターンが通用しない
- グローバル拠点展開→国内標準化なしにツール導入しても機能しない
### SaaS・ITサービス業（自社プロダクト販売）
- 「顧客課題を先読みして提案する」スタイルが属人化している
- 既存顧客での長期関係構築は得意でも新規では勝率が落ちる
- 組織として「何が正解か」を定義できていない
### 美容・化粧品メーカー（代理店経由営業）
- ルート営業から「コト提案・価値提案」へのシフトが求められている
- ブランドリニューアル・新事業（ODM/OEM）での提案型営業への転換が必要
- 代理店・サロンへの「商品を届ける」から「サロンの繁栄を支援する」への変化
### CRM・マーケティング支援業
- 自社がデジタルマーケティングのプロ→ツール・仕組みへの自負がある
- だからこそ「人が動かない」「再現性が作れない」という本質課題に向き合いにくい
- 強みである顧客志向の高さが個人依存になっているという逆説

## 質チェックリスト
文面作成後、以下を確認する。
- [ ] 課題仮説は「主仮説2つ＋各1階層ドリルダウン」の主従構造になっているか（3点並列になっていないか）
- [ ] 主仮説①は「方針と現場の乖離」系、主仮説②は「ナレッジの構造問題」系になっているか
- [ ] 仮説の主語が「御社」ではなく「このフェーズを進める企業」として普遍化されているか
- [ ] 課題仮説ブロックの前に「評価・共感の一文」が置かれているか
- [ ] 現場仮説は「誰が・どんな場面で・何に詰まっているか」まで落ちているか
- [ ] 社内用語（SEP・SYNC・Visualize等）が入っていないか
- [ ] 役職名が未確認の場合、メール本文に記載していないか
- [ ] 仮説の語尾が「〜ではないか」になっているか（断定していないか）
- [ ] 「外側からの仮説にすぎません」の留保が入っているか
- [ ] セミナートリガーが自社か第三者かによって書き出しを変えているか
- [ ] 日程候補が入っているか

## 重要な設計思想
**フォーマットより仮説の解像度が命。**
このスキルのフォーマットを守るだけでは不十分。最も価値が出るのは「企業固有の構造から導かれた課題仮説」の精度。HPを読み込み、採用JDを見て、事業フェーズを掛け合わせて、その会社だけに当てはまる仮説を作ること。
「どこの会社にも当てはまる仮説」はアポが取れない。「この会社だから当てはまる仮説」が読んだ人の心を動かす。
